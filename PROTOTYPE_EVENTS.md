# RogueConst — прототип: разбор каждого события

Шпаргалка для защиты. Здесь по порядку объяснено, из чего собран прототип и что делает каждое из **7 событий** списка `room`. Номера событий совпадают с нумерацией в редакторе Construct 3.

---

## Что показывает прототип

| Требование задания | Как выполнено |
|---|---|
| **Базовое управление** | Ходьба на W A S D в 8 направлениях. Персонаж разворачивается влево или вправо по ходу движения |
| **Камера** | Камера привязана к персонажу (поведение «Следить за»). Комната ровно в размер экрана, поэтому камера показывает комнату целиком, как в The Binding of Isaac |
| **Главная механика игрового цикла** | **Процедурная карта**: бесконечная сетка комнат, переходы через двери, посещённые комнаты запоминаются, счётчик открытых комнат |

**Игровой цикл прототипа:** вошёл в комнату → дошёл до двери → попал в соседнюю комнату → новая комната засчитывается → повтор. В полной игре в этот же цикл добавляется «зачисти комнату, чтобы открыть двери».

---

## Из чего состоит проект

### Макет `start` (1920 × 1080)
Один макет — это **одна комната**. Все комнаты карты — это тот же самый макет, который перезапускается при переходе через дверь. Отличаются они только координатами, которые хранятся в переменных.

### Объекты

| Объект | Тип | Зачем |
|---|---|---|
| `player` | Спрайт | Персонаж. Поведения: **«8 направлений»** (ходьба) и **«Следить за»** (камера) |
| `wall` | Спрайт, 4 штуки | Стены по краям комнаты. Поведение **«Твёрдый»** — сквозь них нельзя пройти |
| `door` | Спрайт, 4 штуки | Двери. У каждой переменная экземпляра **`Dir`**: 0 — левая, 1 — верхняя, 2 — нижняя, 3 — правая |
| `HUD` | Текст | Строка сверху: координаты комнаты, счётчик, подсказка |
| `Keyboard` | Клавиатура | Чтобы события могли проверять нажатые клавиши |
| `Rooms` | Словарь (Dictionary), **глобальный** | «Память» карты: в нём отмечены посещённые комнаты |

### Важные настройки
- **У «8 направлений» выключено «Управление по умолчанию»** (Default controls). Иначе персонаж ходил бы на стрелки. Мы управляем им сами через WASD (события 3–6).
- **«Задать угол» = Нет.** Персонаж не крутится при ходьбе, он только отражается влево и вправо (событие 2).
- **`Rooms` — глобальный объект.** Обычные объекты удаляются при перезапуске макета, а глобальные — нет. Поэтому словарь «помнит» комнаты между переходами.

### Глобальные переменные

| Переменная | Что хранит |
|---|---|
| `RoomX`, `RoomY` | Координаты текущей комнаты на карте. Старт — `0, 0`. Вправо X растёт, вниз Y растёт |
| `RoomKey` | Те же координаты строкой, например `"1,-2"` — ключ для словаря |
| `EnterDir` | Через какую дверь вышли из прошлой комнаты (0–3), `-1` — начало игры |
| `NewRoom` | 1, если игрок в этой комнате впервые, иначе 0 |
| `RoomsVisited` | Сколько разных комнат открыто (старт считается, поэтому начальное значение 1) |
| `Speed` | Скорость ходьбы — 380 |
| `MoveX` | Направление ходьбы по горизонтали в этом кадре: −1, 0 или 1 |

> **Почему глобальные?** Глобальные переменные, как и глобальные объекты, **не сбрасываются при перезапуске макета**. На этом держится вся карта: макет перезапускается, а координаты остаются.

## Событие 1 — «При запуске макета» (вход в комнату)

**Условие:** Система → *При запуске макета* (On start of layout).

**Когда срабатывает:** один раз, в первый кадр после запуска игры **и после каждого перехода через дверь** (событие 7 перезапускает макет).

**Действия по порядку:**

1. **`RoomKey = RoomX & "," & RoomY`**
   Склеивает координаты в строку-ключ. `&` в Construct — это соединение строк. Например, комната `(2, -1)` получает ключ `"2,-1"`.

2. **`NewRoom = (Rooms.Get(RoomKey) = 0) & ((RoomX <> 0) | (RoomY <> 0))`**
   Проверяет, новая ли комната.
   - `Rooms.Get(ключ)` возвращает 0, если такого ключа в словаре ещё нет, то есть игрок здесь не был.
   - Вторая часть исключает стартовую комнату `(0,0)`: она уже посчитана в начальном значении `RoomsVisited = 1`.
   - `=` в выражении даёт 1 или 0, `&` между числами — логическое «И», `|` — «ИЛИ». Итог: 1 или 0.

3. **`Rooms` → Добавить ключ (`RoomKey`, 1)**
   Отмечает комнату как посещённую. Используется именно **«Добавить ключ»** (Add key), а не «Установить ключ» (Set key): «Установить» меняет только уже существующий ключ и для новой комнаты ничего бы не записал.

4. **`RoomsVisited += NewRoom`**
   Прибавляет 1 к счётчику, только если комната новая (прибавляем 1 или 0 — без отдельного условия).

5. **`player` → Задать позицию**
   - X: `(EnterDir = 0) ? 1700 : ((EnterDir = 3) ? 220 : 960)`
   - Y: `(EnterDir = 1) ? 880 : ((EnterDir = 2) ? 200 : 540)`

   Ставит игрока у двери, **противоположной** той, через которую он вышел. Вышел в левую дверь (`EnterDir = 0`) — значит пришёл в соседнюю комнату справа, и появляется у правой стены (x = 1700). `?:` — условный оператор «если ? то : иначе». При старте игры `EnterDir = -1`, и игрок появляется в центре (960, 540).

6. **`player` → 8 направлений → Задать макс. скорость = `Speed`**
   Скорость ходьбы берётся из переменной, чтобы её было легко менять в одном месте.

## Событие 2 — «Каждый тик» (каждый кадр)

**Условие:** Система → *Каждый тик* (Every tick) — выполняется каждый кадр, примерно 60 раз в секунду.

**Действия:**

1. **`MoveX = 0`**
   Обнуляет направление в начале кадра. Ниже события A и D (4 и 6) снова заполнят его, если клавиша зажата. Поэтому порядок событий важен: это событие стоит **выше** событий клавиш.

2. **`player` → Задать ширину = `(MoveX <> 0) ? ((MoveX < 0) ? -95 : 95) : player.Width`**
   Разворачивает персонажа. **Отрицательная ширина в Construct зеркалит спрайт** по горизонтали.
   - идёт влево → ширина −95 (смотрит влево),
   - идёт вправо → 95,
   - не идёт по горизонтали → ширина не меняется, персонаж смотрит туда, куда шёл последний раз.

3. **`HUD` → Задать текст**
   `"Комната: " & RoomKey & "   Открыто комнат: " & RoomsVisited & newline & "WASD — ходьба..."`
   Обновляет строку сверху. `newline` — перенос строки.

4. **`HUD` → Переместить наверх** (Move to top)
   Держит текст поверх всех объектов, чтобы его ничего не перекрывало.

## События 3–6 — «Клавиша удерживается» (W, A, S, D)

**Условие:** Клавиатура → *Клавиша удерживается* (Key is down). Срабатывает **каждый кадр, пока клавиша зажата** — поэтому движение плавное, а не по одному шагу.

| Событие | Клавиша | Код | Действия |
|---|---|---|---|
| 3 | W | 87 | 8 направлений → **Эмулировать управление: вверх** |
| 4 | A | 65 | Эмулировать: **влево**; `MoveX −= 1` |
| 5 | S | 83 | Эмулировать: **вниз** |
| 6 | D | 68 | Эмулировать: **вправо**; `MoveX += 1` |

**Как это работает:**
- **«Эмулировать управление»** (Simulate control) — это то же самое, что нажать стрелку в стандартном управлении «8 направлений», но клавишу выбираем мы. Поведение само считает ускорение, торможение и скорость.
- **Диагональ:** если зажаты W и D, срабатывают оба события, и «8 направлений» сама идёт по диагонали.
- **Стены:** «8 направлений» автоматически не даёт пройти сквозь объекты с поведением **«Твёрдый»**. Отдельные события на столкновение со стенами не нужны.
- `MoveX` меняют только A и D: он нужен для разворота персонажа влево и вправо (событие 2). Вверх и вниз персонаж не зеркалится.
- Если зажать A и D одновременно, `MoveX = −1 + 1 = 0` — персонаж не разворачивается, а «8 направлений» гасит противоположные направления.

## Событие 7 — «Перекрывает дверь» (переход в соседнюю комнату)

**Условие:** `player` → *Перекрывается с другим объектом* (Is overlapping) → `door`.

**Действия:**

1. **`EnterDir = door.Dir`**
   Запоминает, через какую дверь вышли. `door.Dir` берётся у **той самой двери**, которой касается игрок: условие «перекрывается» само выбирает (picking) нужный экземпляр двери.

2. **`RoomX += (door.Dir = 3) − (door.Dir = 0)`**
   **`RoomY += (door.Dir = 2) − (door.Dir = 1)`**

   Сдвиг по карте одной формулой. Сравнение даёт 1 или 0:

   | Дверь | `Dir` | Изменение X | Изменение Y |
   |---|---|---|---|
   | левая | 0 | 0 − 1 = **−1** | 0 |
   | верхняя | 1 | 0 | 0 − 1 = **−1** |
   | нижняя | 2 | 0 | 1 − 0 = **+1** |
   | правая | 3 | 1 − 0 = **+1** | 0 |

3. **Система → Перезапустить макет** (Restart layout)
   Комната «пересоздаётся». Обычные объекты возвращаются в исходное состояние, а глобальные переменные и словарь `Rooms` остаются. Сразу после перезапуска срабатывает **событие 1**: вычисляет новый ключ, отмечает комнату и ставит игрока у нужной двери.

## Как всё работает вместе (пример)

1. Старт: `RoomX = 0, RoomY = 0, EnterDir = −1`. Событие 1: ключ `"0,0"`, игрок в центре, `RoomsVisited = 1`.
2. Игрок держит D (событие 6) → идёт вправо, смотрит вправо (событие 2).
3. Касается правой двери (`Dir = 3`) → событие 7: `EnterDir = 3`, `RoomX = 1`, перезапуск.
4. Событие 1: ключ `"1,0"`, такого в словаре нет → `NewRoom = 1`, `RoomsVisited = 2`. Игрок у **левой** стены (x = 220), как будто вошёл слева.
5. Игрок возвращается через левую дверь → `RoomX = 0`. Ключ `"0,0"` уже есть → `NewRoom = 0`, счётчик не растёт.

## Вопросы, которые могут задать

**— Почему комнат бесконечно много, если макет один?**
Комната определяется только координатами `RoomX, RoomY`. Макет — это «шаблон» комнаты, мы просто перезапускаем его с новыми координатами. Карта создаётся по мере движения игрока — это процедурная генерация «на лету».

**— Как игра помнит, где игрок уже был?**
В глобальном словаре `Rooms`: ключ — координаты комнаты строкой, значение — 1. Глобальные объекты не удаляются при перезапуске макета.

**— Почему не сделать много макетов, по одному на комнату?**
Тогда карта была бы конечной, и на каждую комнату пришлось бы копировать объекты и события. Один макет + координаты дают бесконечную карту и тратят всего 7 событий из лимита бесплатной версии (40).

**— Почему персонаж не проходит сквозь стены, хотя событий на это нет?**
У стен поведение «Твёрдый», а персонаж движется поведением «8 направлений», которое само останавливается о твёрдые объекты.

**— Почему управление не стрелками, а WASD?**
В полной игре стрелки отвечают за стрельбу, поэтому стандартное управление «8 направлений» выключено и заменено эмуляцией на WASD.

**— Где камера?**
У персонажа поведение «Следить за» (Scroll To). Размер макета совпадает с экраном (1920 × 1080), поэтому камера держит в кадре всю комнату — классическая камера рогаликов «одна комната — один экран».

**— Что дальше по игровому циклу?**
В полной версии (ветка `feature/roguelike-gameplay`) поверх этого цикла добавлены: случайная расстановка препятствий в новых комнатах, враги, двери открываются только после зачистки, стрельба, улучшения, этажи со стражами и permadeath.
